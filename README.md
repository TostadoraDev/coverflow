# 💿 Coverflow

**Turn your favorite albums into a living GitHub README gallery.**

Album covers, artist names, release years, and clickable links. No image uploads, Spotify login, API keys, or extra Python packages.

<sub>Made for people who think a GitHub profile can have good music taste, too.</sub>

</div>

---

## Features

- **Automatic artwork:** Fetch album covers and metadata from Apple's public iTunes Search API.
- **No uploaded images:** Display album covers using their hosted image URLs.
- **Your picks, not your history:** Show handpicked favorites, not what you're currently listening to.
- **Clickable covers:** Link to Apple Music/iTunes by default, or supply your own Spotify URL.
- **GitHub-ready layout:** Generate a centered HTML table, with up to four albums per row.
- **Automatic updates:** Refresh on album-list changes, manually, or on a weekly schedule.
- **Zero Python dependencies:** Uses only the Python standard library.
- **Safe README updates:** Only the gallery between two designated markers is rewritten.

## Quick start

Want to use Coverflow **in your own GitHub profile README**? Put its files **in your profile repository** (the repository named exactly like your GitHub username), rather than expecting this repository to change your profile remotely.

1. **Copy these three files** into the repository whose `README.md` should contain the gallery, preserving their paths:
   - [`albums.json`](albums.json)
   - [`scripts/update_music.py`](scripts/update_music.py)
   - [`.github/workflows/music-gallery.yml`](.github/workflows/music-gallery.yml)
2. **Edit `albums.json`** to list the albums you want to feature.
3. **Keep your existing `README.md`.** Add a heading such as `## 🎧 My Music Taste`, followed by the **two HTML comment markers from the Live gallery section above**, exactly as written and in the same order. There must be **exactly one pair** in the entire README.
4. **Commit and push** these changes to your default branch.
5. Open your repository's **Actions** tab, select **Refresh music gallery**, and click **Run workflow**.
6. Once the run succeeds, the action commits the generated gallery into your README. Your other content remains untouched.

> [!IMPORTANT]
> The included workflow edits `README.md` **in the repository where it runs**. For your personal GitHub profile, install it in your **profile repository**, not just in a separate Coverflow repository.

## Choose your albums

Edit [`albums.json`](albums.json):

```json
[
  { "artist": "Tainy", "album": "DATA" },
  { "artist": "Katy Perry", "album": "PRISM" },
  { "artist": "Katy Perry", "album": "Teenage Dream" },
  { "artist": "Travis Scott", "album": "ASTROWORLD" }
]
```

Every entry needs the album title and artist name. Keep them close to the official release names so the search can identify the correct record.

### Link covers to Spotify (optional)

By default, covers open the album's Apple Music/iTunes page. To point to another service, add a `url`:

```json
[
  {
    "artist": "Katy Perry",
    "album": "PRISM",
    "url": "https://open.spotify.com/album/YOUR_REAL_ALBUM_ID"
  }
]
```

This changes **where clicking the cover takes you**. The cover art still comes from the iTunes artwork CDN. Replace `YOUR_REAL_ALBUM_ID` with the actual ID from your album link.

### More albums?

Just add more objects to the JSON array. Coverflow places **four albums per row** automatically. Removing every album produces a small placeholder message instead of an empty table.

## How it works

```text
albums.json
    │
    ▼
Python generator
    │ searches by album + artist
    ▼
iTunes Search API
    │ returns cover URL, artist, title, release date, and album link
    ▼
HTML gallery
    │ replaces only the marked section
    ▼
README.md
    │
    ▼
GitHub Actions commits the change (if there is one)
```

The generator checks artist and album names to reduce incorrect matches. If it cannot confidently identify an album, the run fails with a readable error instead of silently displaying a different one.

**Note:** This is a generated *static* gallery, not a real-time Spotify widget or an embedded music player. GitHub can also cache external images, so cover updates may not appear immediately.

## Automatic refresh

The included [GitHub Actions workflow](.github/workflows/music-gallery.yml) runs:

| Trigger | When |
| --- | --- |
| **Manual** | **Actions → Refresh music gallery → Run workflow** |
| **Albums edited** | A push changes `albums.json` |
| **Generator edited** | A push changes `scripts/update_music.py` |
| **Workflow edited** | A push changes the workflow file |
| **Scheduled** | Every Sunday at **08:17 UTC** |

The workflow uses Python 3.12, then commits **only if `README.md` changed**. Scheduled runs use the default branch and may be delayed or disabled by GitHub after extended repository inactivity.

> [!NOTE]
> The workflow requests `contents: write` so it can commit the generated README. If you get a `403` or `Permission denied`, check the repository's **Settings → Actions → General → Workflow permissions**, as well as any organization policy or branch protection rule that blocks bot pushes.

## Run locally

You can generate the same gallery without GitHub Actions. Install **Python 3.9+**, open a terminal in the project root, and run:

```bash
python scripts/update_music.py
```

On Windows, this may be:

```powershell
py -3 scripts/update_music.py
```

This reads `albums.json`, requests album metadata over the internet, and updates the marked gallery in `README.md`. Review the diff before committing:

```bash
git diff -- README.md
```

No `pip install`, tokens, secrets, or Spotify Developer account are required.

## Customize the layout

The markup is produced by [`render_cell()` and `generate_gallery()`](scripts/update_music.py) in `scripts/update_music.py`.

| Setting | Where | Current value |
| --- | --- | --- |
| Album cover size | `render_cell()` | `145px` wide |
| Table cell width | `render_cell()` | `175px` |
| Albums per row | `generate_gallery()` | `4` |
| Album search region | `find_album()` | `US` |
| Scheduled refresh | `music-gallery.yml` | Sundays, `08:17 UTC` |

You can change the layout in Python and commit your edit: the workflow will rerun. GitHub READMEs restrict CSS and JavaScript, so Coverflow uses basic HTML for reliable rendering.

## Troubleshooting

| Problem | What to try |
| --- | --- |
| `Could not confidently find...` | Check the artist spelling and exact album title. Availability can vary by country. |
| `README.md needs exactly one pair...` | Add the two gallery markers once, in order. Don't duplicate them in examples inside the same README. |
| The workflow doesn't appear | Confirm the YAML file exists on your default branch and Actions is enabled. |
| The gallery doesn't change after editing `README.md` | Run the workflow manually; README-only pushes do not trigger the included workflow. |
| The action cannot push | Check `contents: write`, repository/organization restrictions, and branch protection. |
| Album art doesn't load | Check network/CDN availability. Covers are hosted externally and aren't backed up in this repository. |
| An album links to Apple Music instead of Spotify | Add an explicit `url` to that album in `albums.json`. |

The script currently searches the **US iTunes catalog**. Some regional releases, alternate editions, or similarly named albums may be unavailable or hard to match. If any requested album fails, the script stops instead of creating a partially updated gallery.
